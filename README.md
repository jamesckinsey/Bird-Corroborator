# Bird Corroborator

Bird Corroborator is a lightweight FastAPI companion to BirdNET-Go. It polls BirdNET-Go in batches, stores detections in SQLite, enriches them with independent BirdWeather observations, and serves a local dashboard. BirdNET confidence is retained as evidence and is never an admission threshold.

## NUC deployment architecture

The tested target layout is:

```text
birdpi / Raspberry Pi / 192.168.1.177:8080
  └─ BirdNET-Go (remains running there)
             │ read-only HTTP over the home LAN
             ▼
Intel NUC / Ubuntu 22.04 LTS / Docker
  └─ Bird Corroborator :8000
       ├─ SQLite database
       ├─ BirdWeather enrichment
       └─ cached Wikimedia thumbnails
```

These addresses are deployment configuration, not application constants. `BIRDNET_BASE_URL` may point to any reachable BirdNET-Go instance. The Compose project contains only Corroborator and never controls BirdNET-Go.

## Configuration

Copy `.env.example` to `.env`; `.env` is ignored by Git and excluded from Docker builds. For the described NUC deployment, verify:

```env
BIRDNET_BASE_URL=http://192.168.1.177:8080
CORROBORATOR_DATA_DIR=./data
PUID=1000
PGID=1000
HOME_LATITUDE=42.362
HOME_LONGITUDE=-71.449
BIRDWEATHER_EXCLUDED_STATION_IDS=YOUR_OWN_STATION_ID
```

`CORROBORATOR_DATA_DIR` is a host path mounted at `/data`; SQLite, WAL/SHM files, image thumbnails, and retry state persist there. Use `id -u` and `id -g` for `PUID`/`PGID` if the NUC account is not UID/GID 1000. Coordinates, radius, lookback, cache duration, polling interval, endpoints, and exclusions remain configurable. Multiple excluded BirdWeather station IDs are comma-separated.

There is no minimum BirdNET confidence setting or filter. The normal poll interval remains 300 seconds. A fresh database performs one bounded 12-hour catch-up; a database with its checkpoint goes directly to lightweight recent polling. Stable source IDs prevent duplicates.

## Clean NUC deployment

On the NUC:

```bash
git clone git@github.com:jamesckinsey/Bird-Corroborator.git
cd Bird-Corroborator
cp .env.example .env
nano .env
mkdir -p "${PWD}/data"
docker compose config
docker compose up -d --build
docker ps
curl -s http://localhost:8000/api/v1/status
docker logs --tail 100 bird-corroborator
```

Open `http://<NUC-IP>:8000`. The container listens on `0.0.0.0:8000`. The architecture-neutral Python 3.11 Debian image and dependencies run on Ubuntu 22.04 x86_64; Compose no longer forces ARM. No privileged mode or host monitoring mounts are needed.

For updates:

```bash
cd ~/Bird-Corroborator
git pull
docker compose up -d --build
curl -fsS http://localhost:8000/api/v1/status
```

Routine operations:

```bash
docker compose ps
docker compose logs -f --tail=200 bird-corroborator
docker compose restart bird-corroborator
docker compose down
docker compose up -d
```

## Parallel validation and final data migration

For initial parallel testing, use a fresh NUC `./data` directory. Both Corroborator instances are independent read-only BirdNET-Go HTTP clients and have separate SQLite/image state. Do not copy a live SQLite database as the final authoritative migration because WAL-mode changes may not be captured consistently.

When the NUC instance is validated, perform the final cutover manually:

1. On birdpi, stop **only** the old Corroborator and leave BirdNET-Go running:

   ```bash
   cd ~/Bird-Corroborator
   docker compose down
   ```

2. Make a consistent archive after Corroborator has stopped:

   ```bash
   tar -C /home/jkinsey -czf /tmp/bird-corroborator-data-final.tgz bird-corroborator-data
   scp /tmp/bird-corroborator-data-final.tgz <NUC_USER>@<NUC_IP>:/tmp/
   ```

3. On the NUC, stop only its test Corroborator, preserve its test data if desired, and restore into the configured directory:

   ```bash
   cd ~/Bird-Corroborator
   docker compose down
   mv data "data.parallel-test-$(date +%F-%H%M%S)"
   mkdir data
   tar -xzf /tmp/bird-corroborator-data-final.tgz --strip-components=1 -C data
   sudo chown -R "$(id -u):$(id -g)" data
   docker compose up -d
   curl -fsS http://localhost:8000/api/v1/status
   docker logs --tail 100 bird-corroborator
   ```

4. Confirm the previous checkpoint is present, recent polling resumes, and detection counts do not duplicate. BirdNET-Go stays online throughout.

## Dashboard and performance

`/` is the cached, score-ranked Species Summary. It reads local SQLite with eager-loaded relationships plus one batched image query; it never calls BirdNET-Go, BirdWeather, or Wikimedia, and never downloads or resizes images. Summary results are cached for 60 seconds and invalidated by new detections, completed corroboration, or image changes. INFO logs include one route timing line such as:

```text
Dashboard rendered: route=/ duration=0.006s species=13 summary_cache_hit=true
```

Persistent WebP thumbnails are generated by the background image worker at no more than 320 pixels wide. The first three load normally; later images use lazy loading and browser cache headers. Missing images render the local placeholder immediately.

The System page distinguishes BirdNET HTTP availability from successful parsing/ingestion and shows the sanitized configured host/port. It also reports BirdWeather, SQLite, backlogs, process memory/CPU, system load, available RAM, uptime, and CPU temperature when an unprivileged Linux thermal interface exists. Temperature is optional and displays `Unavailable` otherwise.

## BirdWeather evidence and diagnostics

Evidence means: X unique independent stations within the configured radius (10 miles by default) heard the species Y total times within the configured lookback (24 hours by default). IDs in `BIRDWEATHER_EXCLUDED_STATION_IDS` contribute nothing to counts, distance, timing, or scoring.

INFO logs contain concise per-lookup totals. For temporary station-ID diagnosis, set `LOG_LEVEL=DEBUG`, recreate Corroborator with `docker compose up -d`, and inspect `BirdWeather observation` lines. Restore `LOG_LEVEL=INFO` afterward.

## API, maintenance, and future audio

Main routes include `/api/v1/status`, `/api/v1/detections/today`, `/api/v1/detections/latest`, `/api/v1/species/today`, `/api/v1/nearby/today`, and `/docs`.

```bash
docker compose exec bird-corroborator python -m app.cli catchup --hours 72
docker compose exec bird-corroborator python -m app.cli images-reset
```

Audio playback is not implemented. Current BirdNET parsing preserves the detection `id`, timestamp (`timestamp`, `beginTime`, or date/time), `clipName`, `audio_reference`, or `audioUrl`; the selected clip reference is exposed as `audio_reference`, and the complete source payload remains in `raw_metadata`. Those fields are candidates for a later listen feature without adding polling now.
